## Selected Engineering Work

Most of my personal work centers on taking complex domains, identifying the important state and rules, and turning them into software that stays understandable as it grows.

### Blizzard Lift
An adaptive workout planning and progression platform built with **Java, Spring Boot, React, Azure SQL, and Azure App Service**.

Engineering highlights:
- Models progression as a stateful flow: **Training Max → Prescription → Performance → Evaluation → Progression Event → Updated Baseline**
- Preserves signed workout prescriptions so historical training evidence remains trustworthy even after future state changes
- Uses optimistic versioning to prevent conflicting updates from silently overwriting progression state
- Supports Azure deployment, SQL persistence, authentication, history, analytics, and configurable exercise progression

### Blizzard Habits
A mobile-first habit tracking PWA built with **React, TypeScript, Node/Express, and SQL persistence**.

Engineering highlights:
- Tracks scheduled habits, check-ins, streaks, and weekly completion state
- Supports configurable frequencies, editable habit definitions, soft deletes, and historical preservation
- Uses SQLite locally and Azure SQL for managed production persistence
- Designed as an installable iPhone PWA with a lightweight backend API

### BuilderBlizz / Operator
A governed AI operating framework focused on **persistent context, memory, human authorization, tool use, and reliable execution**.

Engineering highlights:
- Separates human-authored constitutional direction from operational memory and execution state
- Uses persistent local memory and structured task state for continuity across sessions
- Defines explicit boundaries around authority, evidence, approvals, and tool use
- Designed to preserve human control while making long-running AI-assisted work more coherent

### Blizzard GameLab
A **TypeScript/React** game-design workbench for modeling mechanics, tradeoffs, and constrained optimization.

Engineering highlights:
- Represents a game concept as a typed domain model rather than an unstructured prompt
- Uses configurable mechanic weights, synergies, conflicts, complexity effects, and session-pressure rules
- Includes deterministic constrained search for stronger mechanic mixes without pretending the heuristic model predicts market success
- Includes model traceability, unit tests, browser tests, and explicit handling of uncertainty and model limitations

### Notion Data Pipelines
Azure Functions and SQL-backed automation for moving structured personal data into an analytics-ready system.

Engineering highlights:
- Uses **.NET isolated Azure Functions**, scheduled and manual sync flows, pagination, retry logic, and SQL upserts
- Supports incremental synchronization with stored watermarks
- Uses Azure SQL, Key Vault references, and Managed Identity-oriented deployment patterns
- Built around keeping source-system data durable, queryable, and ready for downstream analytics
